## `6844175` feat. .env.example 파일 추가 및 dotenv 연동 - backend/.env.example(DATABASE_URL/JWT_SECRET_KEY/CORS_ORIGINS), frontend/.env.example(VITE_API_BASE_URL) 추가 - python-dotenv로 backend/.env를 실제로 읽어오도록 연결(이전엔 로드하는 코드 자체가 없어 값이 반영 안 됨) - 빈 값(KEY=)이 os.getenv 기본값을 무력화하는 함정 발견해 주석 처리 방식으로 수정, pytest 102개 통과

- 신규 파일: `backend/.env.example`, `frontend/.env.example`
- 수정 파일: `README.md`, `backend/app/auth.py`, `backend/app/database.py`, `backend/app/main.py`, `backend/requirements.txt`

### 목적 및 이유
- AskUserQuestion으로 여러 차례 제시했던 ".env.example 파일 추가"(신규 개발자가 필요한 환경변수를 코드를 뒤져야 알 수 있는 문제)를 오늘 사용자가 선택. 먼저 `os.getenv`/`import.meta.env`를 코드 전체에서 grep으로 전수 확인해, 실제로 쓰이는 환경변수가 백엔드 `DATABASE_URL`/`JWT_SECRET_KEY`/`CORS_ORIGINS`, 프론트엔드 `VITE_API_BASE_URL` 4개뿐임을 확인
- 예시 파일만 달랑 추가하려다, 이 프로젝트에는 `.env` 파일을 실제로 읽어오는 코드가 전혀 없다는 것(= `python-dotenv` 같은 라이브러리가 없어 `os.getenv`가 셸에 직접 export된 값만 봄)을 발견. 이 상태로 `.env.example`만 만들면 사용자가 복사해서 값을 채워도 조용히 무시되는, 오히려 더 헷갈리는 상황이 될 것 같아 `python-dotenv`를 추가하고 `database.py`/`auth.py`/`main.py` — 각각 `os.getenv`를 호출하는 3개 파일 — 맨 위에서 `load_dotenv()`를 명시적으로 호출하도록 연결. (`app.database`가 다른 두 파일에 먼저 import되는 순서를 이용하면 한 곳에만 호출해도 되긴 하지만, 암묵적인 import 순서에 기대는 게 아니라 3곳 모두 명시적으로 호출하는 쪽을 택함 — 나중에 파일이 재구성돼도 깨지지 않도록)
- `load_dotenv()`는 이미 설정된 환경변수를 덮어쓰지 않으므로, Docker/Render처럼 실제 배포 환경변수가 이미 있는 곳에서는 안전하게 아무 영향이 없음(Dockerfile도 `COPY . .`가 없어 `.env`가 이미지에 들어갈 일도 없음)
- **직접 재현해서 찾은 함정**: `.env.example`에 `DATABASE_URL=`처럼 값 없이 키만 남겨두면, python-dotenv가 이를 "빈 문자열이 설정된 상태"로 읽어들여 `os.getenv("DATABASE_URL", "sqlite:///...")`가 기본값이 아니라 빈 문자열을 반환해버림. 실제로 `.env.example`을 그대로 `.env`로 복사해 백엔드를 임포트해보니 SQLAlchemy가 빈 URL을 파싱하다 `ArgumentError`로 바로 죽는 것을 확인. 비워둘 항목은 `KEY=`가 아니라 `# KEY=`로 완전히 주석 처리해야 정말 "설정 안 함"으로 취급된다는 것을 알게 되어, 두 `.env.example` 모두 그 방식으로 다시 작성
- 검증: (1) 주석 처리된 `.env.example`을 그대로 `.env`로 복사한 경우 SECRET_KEY/DATABASE_URL이 코드 기본값 그대로 나오는지, (2) `JWT_SECRET_KEY`/`CORS_ORIGINS`에 실제 값을 채운 경우 그 값이 정확히 반영되는지 둘 다 파이썬 인터프리터로 직접 재현해 확인. pytest 102개는 dotenv 도입과 무관하게 그대로 통과(테스트 환경에는 `.env` 파일이 없어 `load_dotenv()`가 아무 영향 없이 no-op으로 지나감)
- README의 백엔드/프론트엔드 로컬 개발 안내에 `.env.example` → `.env` 복사 안내를 추가
