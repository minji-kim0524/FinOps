- 수정 파일: `README.md`, `backend/app/routers/records.py`, `backend/tests/test_payslip.py`, `frontend/src/App.jsx`, `frontend/src/components/BulkActions.jsx`, `frontend/src/hooks/useSalaryRecords.jsx`

### 목적 및 이유
- AskUserQuestion으로 제시한 후보(급여명세서 일괄 ZIP 다운로드, tax_table.py 죽은 코드 정리, 로그인 보안 강화) 중 사용자가 이 항목을 선택. CSV 일괄 업로드로 여러 직원을 한 번에 계산할 수 있는데, 정작 급여명세서는 건별로만 받을 수 있어 업로드 쪽과 짝이 맞지 않는 기능 공백이었음
- `backend/app/routers/records.py`에 `GET /records/payslips`를 추가. 어제(엑셀 내보내기 필터 버그 수정) 이미 만들어 둔 `apply_record_filters` 헬퍼를 그대로 재사용해, `/records`·`/records/export`와 동일한 검색어·직원명·계산일 범위·급여 범위 필터를 지원하도록 함. 매칭되는 각 레코드에 대해 기존 `build_payslip_pdf(record)`를 그대로 호출해 PDF를 만들고, 표준 라이브러리 `zipfile`로 메모리 상에서 압축해 스트리밍 응답으로 반환(새 외부 의존성 추가 없음)
- 이력이 하나도 없을 때는 엑셀 내보내기의 기존 동작(빈 헤더만 있는 xlsx를 200으로 반환)과 일관되게, 빈 ZIP을 200으로 반환하도록 함 — 별도의 404/400 처리를 추가하지 않고 기존 export 엔드포인트와 동일한 원칙을 따름
- **프론트엔드**: `BulkActions`에 "급여명세서 일괄 다운로드 (ZIP, 현재 필터 적용)" 버튼을 추가하고, 기존 `exportToExcel`과 동일하게 `buildFilterParams()`를 재사용해 화면에 적용된 필터를 그대로 요청에 실음. 로딩 상태(`downloadingPayslips`)도 다른 다운로드 버튼들과 같은 패턴으로 관리
- 검증: pytest에 (1) ZIP 안에 레코드 수만큼 PDF가 정확한 파일명으로 들어있는지 `zipfile`로 직접 열어 확인, (2) 필터가 실제로 반영되는지, (3) 이력이 없을 때 빈 ZIP을 반환하는지, (4) 다른 사용자의 이력이 섞여 들어가지 않는지(소유권 격리) 4개 테스트 추가 — 99개 전부 통과, 커버리지 99% 유지. 부수적으로 이 테스트가 한 요청에서 PDF를 여러 번 생성하면서, 그동안 미검증이던 `payslip.py`의 "폰트가 이미 등록되어 있으면 재등록하지 않고 캐시된 것을 쓰는" 분기도 함께 커버되어 `payslip.py`가 100%가 됨
- vitest 14개·build·oxlint도 기존과 동일하게 통과. 로컬 서버에서 실제로 검색어 필터("홍길동")를 건 상태로 ZIP 버튼을 클릭해 `/records/payslips?search=홍길동` 요청이 정상적으로 나가고, 응답이 실제 ZIP 파일(PK 시그니처, 약 29KB)인 것을 직접 확인
