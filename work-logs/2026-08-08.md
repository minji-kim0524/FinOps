# 2026-08-08

## `ed8c900` chore. 프론트엔드 번들 코드 스플리팅 적용 - vendor(react/antd/recharts) 청크 분리 - chunkSizeWarningLimit 조정 - 프로덕션 빌드 실동작 검증

- 수정 파일: `frontend/vite.config.js`

### 목적 및 이유
- **16단계(프론트엔드 번들 크기 최적화)** 진행: `npm run build` 때마다 뜨던 "500KB 초과 청크" 경고를 해결하고, 실제 로딩 성능/캐싱 구조를 개선
- `manualChunks`로 벤더 코드를 라이브러리별로 분리: `vendor-react`, `vendor-antd`, `vendor-recharts` + 앱 코드. 처음에는 객체 형태로 작성했다가, 이 프로젝트가 Vite 8(Rolldown 기반)이라 `manualChunks`가 함수 형태만 지원한다는 걸 빌드 에러로 발견하고 함수형으로 수정
- `chunkSizeWarningLimit`을 1100으로 조정 — antd는 tree-shaking을 거쳐도 라이브러리 자체가 ~1MB라, 이 경고는 "실수로 전부 한 덩어리가 됐는지"를 감지하는 용도로만 의미가 있고 지금은 의도된 정상 분리 상태이므로 임계값을 실제 상황에 맞게 조정
- 청크 분리 전후로 전체 전송 바이트는 거의 동일(사용하는 라이브러리 자체의 크기이기 때문)하지만, 앱 코드만 담긴 청크는 53KB로 따로 빠져서 이후 기능을 추가해도 사용자가 다시 받는 건 이 작은 청크뿐이고, 라이브러리 청크들은 브라우저가 병렬로 받을 수 있게 됨
- 검증: `npm run build` 경고가 사라진 것을 확인한 뒤, `vite preview`로 실제 프로덕션 빌드를 브라우저에서 구동 — 회원가입/로그인, 급여 계산, 표(antd Table), 차트(recharts), 수정 모달(antd Modal)까지 전부 정상 동작하고 콘솔 에러 없음을 확인. 검증 중 CORS 에러를 한 번 만났는데, 이는 프리뷰 서버 포트(4173)가 백엔드가 허용하는 origin(5173)과 달라서 발생한 테스트 환경 문제였고 포트를 맞추자 바로 해결됨(이번 최적화 작업 자체와는 무관)
