### 목적 및 이유
- 이번 작업은 사용자가 직접 지시한 디자인 개선: "현재 디자인을 사용자 경험(UX)을 높이는 방향으로 반응형으로 진행해줘". 코드만 보고 고치지 않고, 임시 백엔드(SQLite, 스크래치패드의 DB)에 샘플 이력 23건을 넣은 뒤 Claude Browser 패널로 모바일(375)·태블릿(768)·데스크톱 폭을 먼저 확인해 실제 문제를 목록으로 만든 다음 설계
- **수정 전 확인된 문제**: ① 모바일에서 14열 표가 날짜 일부와 고정 "관리" 열만 보여 금액은 가로 스크롤을 해야 보임(태블릿도 실수령액이 화면 밖) ② 계산 폼이 기본값이 채워지면 `0`, `1`, `0`만 보여 무슨 칸인지 알 수 없음(placeholder에만 의존) ③ 화면 고정 테마 버튼이 제목과 겹침 ④ 업로드 버튼 라벨(CSV 컬럼명 나열)이 모바일에서 3줄 ⑤ 필터 6개 컨트롤이 모바일에서 세로를 크게 차지 ⑥ 모바일 차트 X축 직원명이 건너뛰어 표시
- **핵심 설계 — 표 ↔ 카드 전환**: 992px(antd lg) 이상은 기존 표, 미만은 `RecordCardList` 카드(직원명·계산일시, 큰 글씨 실수령액, 세전 총 지급액(급여+상여금)·공제액 합계, "상세 내역 보기"로 공제 항목 전체 펼침, 명세서/수정/삭제 3분할 버튼). 카드에서 "세전 급여"가 아니라 "세전 총 지급액"을 쓴 이유: 실수령액이 (급여+상여금)−공제 이므로 상여금이 있을 때 세전 급여만 보여주면 숫자가 안 맞아 보임(급여명세서 PDF의 라벨과 일치). 표 머리글의 정렬 버튼이 없으므로 같은 정렬 조합(최근 계산순, 실수령액 높은/낮은 순 등)을 선택 상자로 제공하고 `updateSort(field, antdOrder)` 형식 그대로 전달
- **화면 크기 감지는 직접 만든 `useMediaQuery`**: antd `Grid.useBreakpoint`는 마운트 직후 효과가 돌기 전까지 빈 값을 돌려줘 데스크톱에서도 한 프레임 모바일 화면이 비치므로, `useSyncExternalStore`로 첫 렌더부터 `matchMedia` 결과를 쓰도록 구현(jsdom 테스트 환경에서는 `matches:false`라 카드 목록이 기본). 반대로 필터 접기/펼치기는 JS 분기 없이 CSS(`@media`)와 `is-open` 클래스로 처리해 깜빡임 없음
- **입력 UX**: `MoneyInput`(천 단위 쉼표, `inputMode="numeric"`, 원 접미사, 최대 10억을 서버와 같은 `limits.js`에서 가져옴)을 폼·수정 모달·필터에 공용 적용, 부양가족·자녀는 명 접미사. 라벨을 항상 표시하되 E2E가 쓰는 placeholder 문구는 그대로 유지. 좁은 폭(≤480)에서는 이름·급여·상여금은 전체 폭, 부양가족/자녀는 2열로 배치해 세로 길이를 줄임. 넓은 폭(≥1100)에서는 5개 입력칸과 계산 버튼을 한 줄에 배치
- **구조 개선**: 급여 계산 / 일괄 작업 / 계산 이력 / 급여 분석 / 집계를 antd `Card` 섹션으로 나누고(다크 모드는 antd 토큰이 처리), 월별·연도별·직원별 집계는 `Tabs`로 합쳐 세로 길이 절감. 일괄 작업은 "가져오기/내보내기"로 묶고 긴 CSV 컬럼·1MB·1,000건 제한 설명은 버튼 아래 안내 문구로 이동(제한 로직 자체는 그대로). 필터는 모바일에서 검색창만 항상 보이고 나머지는 "필터" 버튼(적용 개수 배지 — 접힌 안에서 걸린 필터를 놓치지 않게)으로 펼침. 테마 토글은 로그인 후 헤더 안으로 옮기고(`App.jsx`가 `themeToggle`을 `AppContent`에 전달) 로그인 전/로딩 중에만 고정 위치 유지. 헤더는 820px 이하에서 제목과 버튼을 세로로 쌓음(버튼이 3개로 늘어 기존 480px 기준으로는 넘침)
- **차트/집계표**: 차트에 `compact` 모드(높이 260, 폰트 11, 직원명 -40° 기울여 전부 표시). 작업 중 브라우저로 확인하다 모바일 Y축 폭 48px에서 "16,000만"의 앞자리가 잘려 "6,000만"으로 보이는 것을 발견해 66px로 확대. 집계표는 `size="small"`, 576px 미만에서 총 공제액·평균 열을 숨기고(antd `responsive`) 첫 열은 `fixed: "left"`. 이력 표의 "실수령액" 열은 가장 중요한 값이라 관리 열 옆 오른쪽 고정
- **기타**: 터치 기기(`pointer: coarse`)에서 버튼 최소 높이 40px, 767px 이하 입력칸 글자 16px(iOS Safari의 포커스 시 자동 확대 방지), `viewport-fit=cover` + safe-area 여백, `#root` 폭 1126→1280·`.app` 1200px로 넓은 화면 활용, antd `ko_KR` 로케일 + dayjs `ko`(빈 표 문구·달력·페이지네이션 한국어), 빈 목록 문구를 "필터 조건에 맞는 이력 없음" vs "아직 이력 없음"으로 구분, `useSalaryRecords`가 `loadingRecords`·`sortBy`·`sortOrder`를 노출
- **시도했다가 되돌린 것**: 이력 표에 `sticky`(머리글 고정)를 켰더니 antd가 머리글과 본문을 별도의 `<table>`로 분리해, E2E의 "첫 번째 표에서 행 찾기" 가정이 깨지고(헤더 행 1개만 잡힘) 보조기기에서도 표가 둘로 읽힘 → 이점 대비 비용이 커 제거. 날짜 선택기의 `inputReadOnly`(모바일 키보드 방지)도 데스크톱 키보드 입력을 막아 제거
- **테스트**: 컴포넌트 테스트가 없던 프로젝트 관례에 예외를 둠(이번에는 컴포넌트 안에 분기 로직이 많아서): `RecordCardList`(필드 표시·직원명 없으면 "-"·상세 펼침/접힘·삭제는 확인 후에만 콜백·정렬 값 매핑·"등록순"은 정렬 해제·페이지 UI 표시 조건), `RecordFilters`(토글 `aria-expanded`·배지 개수·검색어는 배지 제외·최소>최대 안내·쉼표 표기와 쉼표 없는 값 전달), `BulkActions`(ZIP 1,000건 경계·1MB 초과 업로드 즉시 경고), `useMediaQuery`. 테스트 환경은 antd 기본(영어) 로케일이라 페이지 이동은 "다음 페이지"가 아니라 페이지 번호 title로 찾음. E2E는 모바일 시나리오를 "카드로 보임 → 상세 펼침 → 필터 펼침 → 가로 스크롤 없음"으로 교체하고, 금액 입력칸 값 단언을 `1,000,000`(쉼표)로 수정, 모바일에서 이력 표 머리글("계산일시")이 없다는 단언은 집계 탭의 표까지 세지 않도록 머리글 role로 확인
- **검증**: vitest 90개(`npm run test:coverage`, 신규 포함)·Playwright E2E 5개·oxlint(기존 LoginPage 경고만)·프론트 빌드 통과. 브라우저에서 모바일/태블릿/데스크톱/다크 모드/로그인 화면을 눈으로 확인하고, 375px에서 `scrollWidth == clientWidth`(페이지 가로 스크롤 없음), 카드 상세 펼침·필터 토글이 재조회 없이 동작함을 DOM으로 확인(중간에 스크린샷이 한 동작 늦게 찍혀 상태가 어긋나 보인 적이 있어, 이후 `aria-expanded`와 fetch 횟수를 직접 읽어 확인). 확인 후 임시 백엔드 종료·브라우저 해상도/색상 설정 복원
