- 수정 파일: `README.md`, `backend/app/routers/records.py`, `backend/tests/test_main.py`, `frontend/src/App.jsx`, `frontend/src/components/BulkActions.jsx`, `frontend/src/hooks/useSalaryRecords.jsx`

### 목적 및 이유
- AskUserQuestion으로 제시한 후보(CSV 업로드 템플릿 다운로드 제공, 급여명세서 일괄 ZIP 다운로드, 로그인 보안 강화) 중 사용자가 이 항목을 선택. 지금까지는 CSV 일괄 업로드 버튼의 문구(`employee_name, gross_pay, bonus_pay, num_dependents, num_children_8_to_20`)만 보고 사용자가 직접 CSV를 만들어야 했음
- `backend/app/routers/records.py`에 `GET /records/csv-template`을 추가. 예시 2행(상여금 없는 행 하나, 상여금 있는 행 하나)을 포함해 형식을 바로 파악할 수 있게 했고, 특정 사용자의 데이터가 아닌 정적 콘텐츠라 인증을 요구하지 않도록 했음. 이 엔드포인트도 `/records/{record_id}` 계열 동적 경로보다 먼저 두는 기존 라우팅 순서 원칙을 지켜 배치
- Excel(특히 한글 Windows)에서 CSV를 열었을 때 한글이 깨지는 문제를 막기 위해 `utf-8-sig`(BOM 포함)로 인코딩. BOM이 있어도 `pd.read_csv`가 자동으로 이를 인식해 컬럼명이 오염되지 않는지 로컬에서 직접 확인한 뒤 반영
- 가장 신경 쓴 부분은 "템플릿과 실제 업로드 파서가 어긋나지 않는지"였음 — 템플릿의 컬럼 구성이나 헤더가 나중에 `calculate_bulk`와 따로 바뀌면 정작 템플릿을 그대로 올려도 실패하는 상황이 생길 수 있어서, pytest에서 실제로 템플릿 응답을 그대로 `/calculate/bulk`에 업로드해 정상 계산되는지 확인하는 회귀 테스트를 추가함(향후 두 코드가 어긋나면 이 테스트가 바로 잡아줌)
- 프론트엔드는 `BulkActions`에 "CSV 템플릿 다운로드" 버튼을 업로드 버튼보다 앞에 배치하고, 기존 `exportToExcel`/`downloadPayslip`과 동일한 패턴(`api.get(..., {responseType: "blob"})` + `downloadBlob`)으로 `downloadCsvTemplate`을 구현
- 검증: pytest 95개 전부 통과(커버리지 99% 유지), vitest 14개·build·oxlint 통과. 로컬 서버에서 실제 버튼을 클릭해 `GET /records/csv-template` 요청이 200으로 응답하는 것을 브라우저에서 직접 확인
