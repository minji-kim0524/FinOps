## `cb71991` test. 백엔드 테스트 커버리지 측정 도입 - pytest-cov 추가(.coveragerc로 app/ 한정), CI에 --cov-report 및 HTML 아티팩트 업로드 반영 - 실측 97% 중 의미 있는 gap(health 미검증, 삭제된 사용자 토큰, CSV 파싱 실패, 폰트 없음 에러) 테스트 보강해 98%로 개선 - README에 커버리지 확인 방법 문서화

- 신규 파일: `backend/.coveragerc`
- 수정 파일: `.github/workflows/ci.yml`, `.gitignore`, `README.md`, `backend/requirements-dev.txt`, `backend/tests/test_auth.py`, `backend/tests/test_main.py`, `backend/tests/test_payslip.py`

### 목적 및 이유
- AskUserQuestion으로 제시한 후보(이력 표 정렬 서버 사이드 전환, 로그인 보안 강화, 백엔드 테스트 커버리지 측정) 중 사용자가 이 항목을 선택. pytest 83개가 통과하고는 있었지만 실제로 코드의 어느 부분이 테스트되고 있는지는 측정된 적이 없었음
- `requirements-dev.txt`에 `pytest-cov`를 추가하고, 측정 대상을 `app/`으로 한정하는 `backend/.coveragerc`를 새로 작성. `pytest --cov`만으로 바로 동작하는지 로컬에서 확인
- 처음 측정한 커버리지는 97%(466줄 중 12줄 미검증)였고, `--cov-report=term-missing`으로 나온 미검증 줄 번호를 하나하나 직접 열어 확인:
  - `app/main.py`의 `/health` 엔드포인트가 테스트에서 단 한 번도 호출된 적이 없었음 → `test_main.py`에 추가
  - `app/auth.py`의 `get_current_user`에서 "JWT는 유효하지만 발급 이후 계정이 DB에서 삭제된 경우" 401 분기가 미검증 → 테스트 안에서 직접 DB의 User row를 삭제해 재현하는 테스트를 `test_auth.py`에 추가
  - `app/routers/records.py`의 `/calculate/bulk`에서 `pd.read_csv`가 예외를 던지는 분기(파싱 불가능한 CSV)가 미검증 → 빈 파일을 업로드하는 테스트를 `test_main.py`에 추가
  - `app/payslip.py`의 "한글 폰트를 서버에서 전혀 찾을 수 없을 때" `RuntimeError`를 던지는 분기가 미검증 → 실제 배포 환경에 나눔고딕/AppleGothic이 없는 상황을 monkeypatch(`pdfmetrics.getRegisteredFontNames`, `Path.exists`)로 재현하는 단위 테스트를 `test_payslip.py`에 추가
  - 반대로 손대지 않고 남겨둔 gap도 있음: `app/database.py`의 `get_db()`는 테스트에서 항상 `dependency_overrides`로 대체되어 실제 제너레이터가 실행될 일이 없고, `app/tax_table.py`의 방어적 fallback 두 줄은 현재 유일한 호출부(`_lookup_single`)의 조건상 도달이 원천적으로 불가능한 코드라, 억지로 커버리지를 채우기보다 그대로 남겨 회고 시 다시 판단할 수 있게 함
- 검증 테스트 4개를 추가한 뒤 재측정하니 87개 전부 통과, 커버리지 97%→98%로 개선
- CI(`backend-tests` 잡)에도 `--cov --cov-report=term-missing --cov-report=html`을 추가해 실행마다 로그에 라인별 리포트를 남기고, HTML 리포트를 `coverage-report` 아티팩트로 업로드하도록 설정(기존 E2E 실패 시 `playwright-report`를 올리던 패턴과 동일하게, 단 이건 실패 여부와 무관하게 항상 업로드). README에도 로컬에서 커버리지를 확인하는 명령어를 문서화
- `.coverage`/`htmlcov/`는 실행할 때마다 생성되는 산출물이라 `.gitignore`에 추가
