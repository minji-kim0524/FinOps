- 신규 파일: `e2e/package.json`, `e2e/package-lock.json`, `e2e/playwright.config.js`, `e2e/tests/salary-flow.spec.js`
- 수정 파일: `.github/workflows/ci.yml`, `.gitignore`, `frontend/src/App.jsx`, `frontend/src/LoginPage.jsx`

### 목적 및 이유
- 22단계에서 만든 프론트엔드 테스트는 컴포넌트 단위(모킹된 API)였고, 로그인부터 계산·수정·삭제까지 실제로 브라우저에서 이어지는 전체 흐름을 검증하는 테스트는 없었음. 이를 Playwright로 보완
- 저장소 루트에 `e2e/` 디렉토리를 별도로 만들어 Playwright를 독립적으로 구성. `playwright.config.js`의 `webServer` 배열 기능으로 백엔드(`backend/venv/bin/uvicorn`)와 프론트엔드(`npm run dev`)를 테스트 실행 시 자동으로 함께 띄우도록 설정
- `tests/salary-flow.spec.js`: 매번 고유한 사용자명(타임스탬프 기반)으로 회원가입 → 계산(세전 300만원) → 표에 정확한 실수령액 표시 확인 → 수정 모달에서 세전 급여를 500만원으로 변경 후 재계산된 값 확인 → 삭제 → 로그아웃까지 실제 Chromium 브라우저로 검증하는 테스트 1개 작성
- **테스트 작성 중 실제 버그 발견**: 수정 모달의 "세전 급여" 입력창에 `getByLabel`로 접근이 안 돼서 원인을 추적한 결과, 계산 폼과 수정 모달 폼이 둘 다 `Form.Item name="gross_pay"`를 쓰는데 두 `<Form>`에 `name` prop이 없어 antd가 만드는 DOM `id`가 서로 충돌하고 있었음 — 라벨이 입력창과 제대로 연결되지 않는 실제 접근성 문제(스크린리더 등에서 라벨을 못 읽는 문제)였음. `App.jsx`의 계산/수정/비밀번호변경 폼과 `LoginPage.jsx`의 로그인/회원가입 폼, 총 4개 `<Form>`에 각각 고유한 `name`을 부여해 근본 원인을 해결
- 테스트 과정에서 recharts 차트가 남기는 잔여 DOM 텍스트(툴팁/축 라벨) 때문에 `getByText`로 전체 페이지를 검색하는 삭제 확인 assertion이 오탐을 일으켜서, 표의 셀(`getByRole("cell", ...)`)만 특정해서 확인하도록 수정
- `.github/workflows/ci.yml`: `e2e-tests` job 신규 추가. Python+Node를 모두 셋업하고, 백엔드 venv 구성 → 프론트엔드/e2e 의존성 설치 → Playwright Chromium 설치 → 테스트 실행 순으로 진행. 실패 시 리포트를 아티팩트로 업로드해 원인 확인이 쉽도록 함
- `.gitignore`: Playwright가 생성하는 `test-results/`, `playwright-report/` 추가
- 검증: 프론트엔드 유닛 테스트 7개 회귀 없음 확인 → E2E 테스트 로컬에서 통과 → 브라우저에서 콘솔 에러·경고 없음 재확인 (Form id 수정이 다른 곳에 부작용을 안 만들었는지 확인)
