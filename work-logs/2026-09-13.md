## `820cc4c` fix. 엑셀 내보내기가 현재 필터를 무시하던 문제 수정 - /records/export가 /records와 동일한 검색·직원명·기간·급여 범위 필터를 받아 적용하도록 수정(공통 로직은 apply_record_filters로 추출) - 프론트엔드도 조회/내보내기가 같은 필터 파라미터를 공유하도록 변경 - pytest 89개(신규 2개 포함)/vitest 14개 통과, 실제 브라우저에서 필터 적용 후 내보내기 요청 확인

- 수정 파일: `backend/app/routers/records.py`, `backend/app/services/records.py`, `backend/tests/test_export.py`, `frontend/src/hooks/useSalaryRecords.jsx`

### 목적 및 이유
- AskUserQuestion으로 제시한 후보(엑셀 내보내기가 현재 필터를 무시함, 이력 표 정렬을 서버 사이드로 전환, 로그인 보안 강화) 중 사용자가 이 항목을 선택. 코드를 직접 읽어 확인한 결과, `/records`(이력 목록)는 검색어·직원명·계산일 범위·급여 범위 필터를 모두 지원하는데 `/records/export`는 필터 파라미터 자체가 없어 화면에서 아무리 좁혀도 항상 전체 이력을 내보내는 것을 확인
- **백엔드**: `list_records`와 `export_records`에 거의 동일하게 반복되던 6개 필터 `if` 블록을 `app/services/records.py`의 `apply_record_filters(query, ...)` 공통 함수로 추출. 두 라우터 모두 이 함수를 호출하도록 바꿔, 앞으로 필터 조건이 추가/변경될 때 한 곳만 고치면 되도록 함. 이 과정에서 `routers/records.py`에 남아 있던 미사용 `datetime` import도 함께 정리
- **프론트엔드**: `useSalaryRecords.jsx`에서 `fetchRecords`가 매번 새로 조립하던 필터 쿼리 파라미터를 `buildFilterParams()`로 뽑아내고, `exportToExcel`도 같은 함수를 호출하도록 수정 — 화면에 적용된 필터와 다운로드되는 엑셀의 범위가 항상 일치하도록 함
- 검증: pytest에 직원명 필터/급여 범위 필터로 export한 결과가 실제로 좁혀지는지 확인하는 테스트 2개를 추가해 89개 전부 통과(커버리지 99%). vitest 14개·build·oxlint도 기존과 동일하게 통과
- 로컬에 실제 서버를 띄우고, AntD `Select` 드롭다운(직원 선택)은 이 세션의 브라우저 자동화 도구로 여러 번 시도해도 선택이 반영되지 않는 문제가 재발해(과거에도 동일 이슈 있었음), 같은 필터 로직 경로를 타는 검색어 입력(`직원명으로 검색`, 일반 텍스트 인풋)으로 우회 검증. 검색어를 입력한 상태에서 실제로 "엑셀로 내보내기" 버튼을 클릭해, 네트워크 요청이 `/records/export?search=홍길동`처럼 필터가 그대로 반영되어 나가는 것을 직접 확인
