# 2026-09-02

## `811afb9` fix. 다크모드/UI 접근성 개선 - 라이트/다크 모드 placeholder 명암비가 WCAG AA(4.5:1) 미달이던 문제 수정 - 직원 선택 드롭다운에 누락된 접근성 라벨(aria-label) 추가 - 브라우저에서 실측 명암비 검증

- 수정 파일: `README.md`, `frontend/src/App.jsx`

### 목적 및 이유
- "이메일 알림/자동화 기능 / 다크모드·UI 접근성 개선 / 다른 제안" 중 다크모드·UI 접근성 개선을 선택. 지금까지 다크모드는 있었지만(antd `darkAlgorithm` 전환) 실제 접근성 관점에서 점검된 적은 없었음
- 육안 확인이 아니라, 브라우저에서 직접 JS로 실제 렌더링된 색상을 계산해 WCAG 명암비 공식(상대 휘도 기반)으로 측정하는 방식으로 점검. `read_page`의 접근성 트리에서 이름 없는 `button`이 다수 나왔지만, 대부분은 텍스트가 자식 요소로 들어있어 실제 브라우저/스크린리더는 "name from content"로 정상 인식하는 도구 자체의 한계(오탐)였음을 대조 확인 후 걸러냄
- 실측으로 확인된 진짜 문제 2가지만 수정:
  1. **입력창 placeholder 명암비 부족**: 라이트 모드 1.83:1, 다크 모드 2.26:1로 WCAG AA 기준(4.5:1)에 크게 못 미침 — antd 기본 `colorTextPlaceholder` 토큰 자체의 문제라 우리 커스텀 색상과 무관하게 라이트/다크 둘 다 해당됨. `ConfigProvider`의 `theme.token.colorTextPlaceholder`를 테마별로 재정의(라이트 `rgba(0,0,0,0.55)`, 다크 `rgba(255,255,255,0.5)`)해 각각 4.76:1 / 5.26:1로 개선
  2. **"직원 선택" 드롭다운에 접근성 라벨 누락**: 다른 필터 입력들은 네이티브 `<input>`이라 `placeholder`가 브라우저에 의해 자동으로 접근 가능한 이름으로 노출되지만, antd `<Select>`는 div 기반 커스텀 위젯이라 placeholder만으로는 스크린리더에 이름이 전달되지 않음. `aria-label="직원 선택"` 추가로 해결
- 점검했지만 문제없었던 항목(수정하지 않음): 키보드 포커스 링(전 요소 잘 보임), 테이블 셀 텍스트 명암비(13:1), 회원가입 폼의 힌트 텍스트(13:1, 별도 토큰이라 placeholder와 무관), 아이콘 전용 버튼(테마 토글은 이미 `aria-label` 있었고 나머지는 텍스트 병기)
- 검증: 수정 전/후 명암비를 브라우저에서 직접 재계산해 라이트 1.83→4.76, 다크 2.26→5.26로 개선됐음을 수치로 확인. `read_page`로 "직원 선택" combobox에 이름이 정상 노출되는 것도 확인. 프론트엔드 테스트 14개 회귀 없이 통과
