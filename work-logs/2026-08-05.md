## `61cb475` chore. GitHub Actions CI 구축 - push/PR마다 백엔드 pytest 및 프론트엔드 빌드 자동 검증

- 신규 파일: `.github/workflows/ci.yml`

### 목적 및 이유
- **14단계(CI 자동화 구축)** 진행: 프로젝트 초기에 계산 로직을 검증할 때 Jenkins 대신 로컬 pytest를 선택했었는데(1단계), 이제 배포까지 끝난 시점에 그 pytest를 커밋·PR마다 자동으로 돌려주는 CI로 자연스럽게 확장
- `ci.yml`: `main` 브랜치로 push되거나 그쪽으로 PR이 열릴 때마다 두 개의 job이 실행되도록 구성
  - `backend-tests`: Python 3.11 환경에서 `backend/requirements.txt` 설치 후 pytest 실행
  - `frontend-build`: Node 20 환경에서 `npm ci` + `npm run build`로 프론트엔드가 실제로 빌드되는지 검증
- 워크플로우 작성 중 발견한 문제: 처음에는 `pytest -v`(bare 명령)로 작성했는데, 로컬에서 재현해보니 `ModuleNotFoundError: No module named 'app'`가 발생함. 지금까지 계속 써온 `python -m pytest`는 파이썬이 현재 디렉토리를 자동으로 `sys.path`에 추가해주는데, bare `pytest` 실행 파일은 그 방식이 아니라서 `app` 패키지를 못 찾는 것으로 확인. CI에서도 똑같이 실패했을 것이므로 `python -m pytest -v`로 수정
- 검증: 로컬에서 `python -m pytest -v`(21개 테스트 통과), `npm ci`+`npm run build`(프로덕션 빌드 성공)를 미리 재현해 CI가 실제로 통과할 명령인지 확인 후 커밋
