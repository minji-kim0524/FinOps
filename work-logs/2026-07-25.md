## `abc6f13` feat. Docker 인프라 구축 - 백엔드/프론트엔드 Dockerfile 작성 - docker-compose로 통합 실행 환경 구성 - SQLite 데이터 영구 저장을 위한 볼륨 설정

- 신규 파일: `backend/Dockerfile`, `backend/.dockerignore`, `frontend/Dockerfile`, `frontend/.dockerignore`, `docker-compose.yml`
- 수정 파일: `backend/app/database.py`

### 목적 및 이유
- **4단계(Docker 패키징)** 구현: 로컬 환경에 의존하던 실행 방식을, 어떤 컴퓨터에서든 동일하게 재현 가능하도록 컨테이너로 포장
- `backend/app/database.py`: DB 경로를 하드코딩(`sqlite:///./finops.db`)하지 않고 `DATABASE_URL` 환경변수로 지정 가능하도록 수정 — Docker 볼륨 경로를 컨테이너 밖에서 주입하기 위함
- `backend/Dockerfile`: `requirements.txt` 설치 → 앱 코드 복사 순서로 구성해, 코드만 바뀌었을 때 의존성 설치 레이어를 재사용(캐시)하도록 함
- `frontend/Dockerfile`: `npm run dev -- --host 0.0.0.0`으로 실행 — 기본값(localhost만 허용)으로는 컨테이너 밖 브라우저에서 접근이 안 되므로 외부 접근을 허용하도록 설정
- `.dockerignore` (양쪽): `venv/`, `node_modules/` 등 로컬 전용 파일을 이미지에서 제외해 빌드 용량/속도 최적화
- `docker-compose.yml`: backend/frontend 두 서비스를 한 번에 빌드·기동. `backend_data`라는 named volume을 `/app/data`에 연결해, 컨테이너를 삭제(`down`)하고 다시 만들어도(`up`) SQLite 데이터가 보존되도록 구성
- 검증:
  - `docker compose up --build`로 두 컨테이너 정상 기동 확인
  - 브라우저에서 실제 계산 요청 → 결과 표시 확인
  - `docker compose restart backend` 및 `docker compose down` → `up` 반복 후에도 `/records` 조회 결과가 유지되어 volume 영속성 검증 완료
