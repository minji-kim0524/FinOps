### 목적 및 이유
- "4대보험 요율 정확도 개선(완료) / 이력 페이지네이션 서버측 전환 / 이메일 알림·자동화 기능 / 다른 제안" 중 이력 페이지네이션 서버측 전환을 선택. 기존에는 `GET /records`가 사용자의 전체 이력을 한 번에 내려받고, antd `Table`이 프론트에서만 10건씩 나눠 보여주는 방식이라 이력이 많아질수록 매번 전체 데이터를 불러오는 것이 부담이 될 수 있었음
- `main.py`: `list_records`에 `page`/`page_size` 쿼리 파라미터를 추가하고, 기존에 프론트에서 처리하던 필터(직원명 검색, 직원 정확히 일치, 계산일 범위, 최소/최대 급여)를 전부 SQLAlchemy 쿼리 조건(`ilike`, `==`, `>=`/`<=`)으로 옮김. 응답 형태를 기존의 배열에서 `{items, total, page, page_size}` 객체로 변경
- 이 변경이 응답 스키마를 바꾸는 것이라, `/records`를 사용하는 기존 테스트(`test_main.py`, `test_ownership.py`)들이 전부 옛 배열 형태를 기대하고 있어 실패하는 것을 확인하고 `body["items"]`/`body["total"]` 형태로 일괄 수정
- `App.jsx`: 기존에 전체 이력을 받아 `useMemo`로 클라이언트 필터링하던 `filteredRecords`를 제거. 대신 검색어·직원·계산일·급여 범위가 바뀌면 페이지를 1로 리셋하고 서버에 새로 요청하도록 재구성. 검색어 입력창은 매 입력마다 요청을 보내지 않도록 300ms 디바운스를 추가. 직원 선택 드롭다운은 (일부 페이지 데이터만 가진) `records` 대신, 이미 전체 이력을 집계하는 `employeeSummary`에서 목록을 가져오도록 변경해 페이지에 상관없이 항상 전체 직원 목록이 보이게 함. "세전 급여 vs 실수령액" 막대 그래프도 이제 현재 페이지 데이터만 반영하므로 제목에 "(현재 페이지)"를 명시
- 삭제 후 현재 페이지의 마지막 항목이 사라지는 경우를 대비해, 삭제 결과가 빈 페이지이고 1페이지가 아니면 자동으로 이전 페이지로 이동하도록 처리
- `test_records_pagination.py`: 기본 페이지 크기, 다음 페이지 조회, 커스텀 페이지 크기, 검색어 부분일치, 직원명 정확 일치, 급여 범위, 계산일 범위 필터까지 7개 테스트 신규 작성
- E2E 테스트: 12건을 실제로 계산해 1페이지(헤더+데이터 10행)와 2페이지(헤더+데이터 2행) 전환이 올바른지 검증하는 테스트 신규 추가
- 검증: pytest 77개, 프론트엔드 테스트 14개, Playwright E2E 3개 전부 통과. 브라우저에서 직접 13건의 데이터를 만들어 1페이지에 10건만 로드되는 것, 직원별 집계는 13명 전체가 나오는 것을 확인. 페이지 전환과 검색어 필터는 네트워크 요청 로그로 `GET /records?page=2&page_size=10`, `GET /records?page=1&page_size=10&search=직원3` 형태로 정확히 서버에 전달되고 결과가 필터링되는 것을 실측 확인
- 참고: 이 작업 도중 진행 상황을 안내하는 중간 문구("Now let's implement...")가 영어로 나간 것을 사용자가 재차 지적함. 최종 요약은 한국어였지만 중간 내레이션이 영어였던 것이 문제로 지적되어, 관련 메모리(`feedback_respond_in_korean.md`)를 이 사례를 근거로 더 명확하게 갱신함(중간 문구도 최종 요약과 동일하게 한국어로 작성해야 함을 명시)
