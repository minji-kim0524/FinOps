- 신규 파일: `backend/scripts/backup_db.sh`, `backend/scripts/restore_db.sh`
- 수정 파일: `.gitignore`, `README.md`

### 목적 및 이유
- Render 대시보드에서 `finops-db`(무료 플랜 PostgreSQL)가 "Suspended by Render" 상태로 정지되고, 여기에 의존하는 `finops-backend`도 배포 시작 시 실행되는 `alembic upgrade head`가 DB에 연결하지 못해 "Failed deploy" 상태가 된 것을 사용자가 확인. 무료 플랜 DB는 만료/정책상 정지될 수 있어, 정지·삭제 시 데이터를 복구할 수 있는 안전장치가 없다는 점이 리스크로 드러남
- 이를 계기로 pg_dump/psql 기반 백업·복원 스크립트를 `backend/scripts/`에 추가. Render에 배포된 DB를 백업하려면 백엔드 서비스가 쓰는 내부 연결 문자열이 아니라 Render 대시보드의 "External Connection String"이 필요하다는 점을 스크립트 주석과 README에 함께 문서화
- `backup_db.sh`는 `DATABASE_URL` 환경 변수(PostgreSQL 전용)를 받아 `pg_dump | gzip`으로 `backend/backups/finops_backup_YYYYmmdd_HHMMSS.sql.gz`를 생성. `DATABASE_URL` 누락, SQLite URL 입력(로컬 기본값은 파일 복사로 충분해 스크립트 대상이 아님), `pg_dump` 미설치 등 사전 조건을 검사해 명확한 한국어 에러 메시지로 안내
- `restore_db.sh`는 백업 파일을 `gunzip | psql`로 복원. 대상 DB의 기존 데이터를 덮어쓰는 파괴적 작업이라 실행 시 "yes" 입력 확인 프롬프트를 거치도록 해 실수로 인한 데이터 유실을 방지
- 백업 파일이 쌓이는 `backend/backups/`는 `.gitignore`에 추가해 git 커밋 대상에서 제외
- 검증: Docker 데몬이 이 환경에서 사용 불가해, 로컬에 `initdb`/`pg_ctl`로 임시 PostgreSQL 클러스터를 직접 띄워 테스트. (1) `backup_db.sh`/`restore_db.sh`를 필수 인자 누락·잘못된 인자로 실행해 각 에러 처리 경로가 의도한 메시지와 함께 종료되는지 확인 (2) 임시 DB에 테스트 테이블·데이터 생성 → `backup_db.sh`로 백업 → 테이블을 `DROP`해 데이터 유실 상황 재현 → `restore_db.sh`로 복원 → 원본과 동일한 데이터가 복구되는지 직접 확인. 테스트에 사용한 임시 PostgreSQL 클러스터와 백업 산출물은 검증 후 모두 정리
