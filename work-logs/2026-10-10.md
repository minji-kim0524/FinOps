### 목적 및 이유
- AskUserQuestion으로 제시한 세 후보(계산 직후 결과 바로 보여주기, 비밀번호 변경·재설정 후 기존 토큰 무효화, 아이디 열거 방지) 중 사용자가 첫 번째를 선택. 직전 반응형 작업 때 코드를 읽다 확인한 UX 문제에서 출발: 계산하면 "계산이 완료되었습니다" 토스트만 뜨고, 이력 목록의 기본 정렬이 등록순(id 오름차순, `apply_record_sort`의 기본값)이라 방금 만든 이력이 **마지막 페이지**에 들어가 결과를 바로 확인할 수 없었음. 이력이 10건을 넘으면 사용자는 2페이지 이상을 넘겨 찾아야 함
- **설계 선택**: 기본 정렬을 최근 계산순으로 바꾸는 방법도 있었지만 기존 동작·서버 정렬 규칙·E2E(이력 10건 초과 페이지네이션 등)에 파급이 커서 하지 않고, 폼 바로 아래의 결과 패널(`CalculationResult`)과 "이력에서 보기" 버튼으로 풀었음. 서버가 `/calculate`에서 이미 저장된 이력 전체(공제 항목 포함)를 돌려주므로 별도 재계산·재조회 없이 응답을 그대로 표시 — `submitCalculation`이 `response.data`를 반환하도록 한 줄 변경
- 패널 내용: 직원명(없으면 "이름 없음"), 큰 글씨 실수령액, 세전 총 지급액(급여+상여금 — 이력 카드와 급여명세서 PDF와 같은 기준이라 숫자가 맞아떨어짐), 공제액 합계, 공제 항목 6가지(국민연금·건강보험·장기요양보험·고용보험·소득세·지방소득세), "이력에서 보기"·"닫기". 항목 이름·순서는 `utils/payBreakdown.js`(`DEDUCTION_ROWS`, `DETAIL_ROWS`)로 분리해 이력 카드의 상세 내역과 공유(기존 `RecordCardList`의 상수를 옮겨 중복 제거)
- **접근성/움직임**: `role="status"` + `aria-label`로 결과가 나타난 것을 스크린리더가 알 수 있게 함. 좁은 화면에서는 결과가 폼 아래라 화면 밖일 수 있어 `scrollIntoView({block:"nearest"})`로 자동 스크롤하되, `prefers-reduced-motion: reduce`이면 부드러운 스크롤 대신 즉시 이동. jsdom에는 `scrollIntoView`가 없어 `?.`로 호출
- **"이력에서 보기"**: `updateSort("created_at", "descend")` + `setPage(1)` 후 이력 섹션으로 스크롤. `updateSort`는 정렬이 같으면 조기 반환해 페이지를 되돌리지 않으므로 `setPage(1)`을 따로 호출. 이력 섹션 `Card`에 ref를 걸고 `.app-section`에 `scroll-margin-top: 12px`를 줘 섹션 제목이 화면 맨 끝에 붙지 않게 함
- React 19이라 `CalculationResult`는 `forwardRef` 없이 `ref`를 일반 prop으로 받아 antd `Card`에 전달
- **브라우저 검증**: 임시 백엔드(스크래치패드 SQLite)와 Vite 개발 서버로, 모바일(375)에서 실제로 폼에 입력해 계산 → 토스트 + 폼 초기화 + 결과 패널(홍길동 3,000,000원 → 2,636,093원 — 기존 E2E에서 쓰던 알려진 값과 일치)이 보이고 자동 스크롤됨을 확인. "이력에서 보기"를 누르면 정렬 선택 상자가 "최근 계산순"으로 바뀌고 첫 카드가 방금 계산한 항목으로 바뀜(클릭 직후 `historyTop`이 1328이어서 실패로 오해할 뻔했으나, 부드러운 스크롤이 진행 중이었을 뿐 1.5초 뒤 0으로 수렴함을 재측정해 확인). 데스크톱(1280)에서는 Enter 키로 제출해도 패널이 폼 아래에 가로로 넓게 보임. 검증 후 임시 백엔드 종료, 브라우저 해상도 복원. 중간에 하루가 지나 Vite 개발 서버가 내려가 있어 `preview_start`로 다시 띄움
- **테스트**: `CalculationResult` 단위 5개(실수령액·세전 총 지급액·공제액 합계, 공제 6항목의 라벨과 금액 짝, 이름 없음, 콜백, status 역할). 프로젝트에 없던 **`AppContent` 통합 테스트**를 새로 추가(api 모킹, 무거운 차트 두 개는 jsdom에서 크기를 못 재 경고만 늘려 모킹으로 비움): 계산하면 서버 응답이 패널에 보이고 `/calculate` 요청 본문이 정확하며 폼이 초기화됨, 서버 오류면 패널이 뜨지 않음, 닫기, "이력에서 보기" 클릭 시 `/records`를 `page:1, sort_by:"created_at", sort_order:"desc"`로 다시 조회.
