## `6abf5f2` fix. 최소/최대 급여 필터 역전 시 안내 문구 추가 - 최소 급여가 최대 급여보다 크면 결과가 조용히 0건이 되던 것을, 입력창 error 상태와 안내 문구로 원인을 알 수 있게 수정 - E2E 검증은 회원가입 rate limit 회귀를 피하기 위해 기존 로그인 흐름 안에 포함, vitest 14개/E2E 5개 통과

- 수정 파일: `e2e/tests/salary-flow.spec.js`, `frontend/src/components/RecordFilters.jsx`

### 목적 및 이유
- AskUserQuestion으로 제시한 후보(로그인 보안 강화, 최소/최대 급여 필터 역전 시 안내 버그) 중 사용자가 이 항목을 선택. 최소 급여에 최대 급여보다 큰 값을 넣으면 서버 쿼리 조건상(`gross_pay >= min AND gross_pay <= max`) 결과가 항상 0건이 되는데, 필터 자체는 "정상적으로" 적용된 것이라 화면에는 아무 안내 없이 표만 비어 보여 사용자가 원인을 알 수 없었던 것을 코드로 확인
- `frontend/src/components/RecordFilters.jsx`에 `isRangeInverted = minGrossPay != null && maxGrossPay != null && minGrossPay > maxGrossPay` 조건을 추가해, 역전 상태일 때 두 `InputNumber`에 `status="error"`(빨간 테두리)를 주고 그 아래 `최소 급여가 최대 급여보다 커서 조회 결과가 없습니다. 값을 확인해주세요.` 문구를 표시. 데이터 조회 로직(`useSalaryRecords.jsx`)은 건드리지 않고 순수하게 프레젠테이션 컴포넌트에서만 처리해, 범위가 역전돼도 요청 자체는 그대로 나가고(백엔드 동작 변화 없음) 화면에 이유만 알려주는 방식으로 최소한의 변경에 그침
- 로컬 브라우저에서 최소 5,000,000/최대 1,000,000을 입력해 경고가 뜨는 것을, 다시 정상 범위로 되돌려 경고가 사라지는 것을 직접 확인
- **E2E 테스트를 추가하는 과정에서 겪은 문제**: 처음엔 이 기능만을 위한 새 테스트를 독립적으로 추가했는데(회원가입부터 새로 진행), 전체 Playwright 스위트를 돌려보니 회원가입 호출이 기존 5회에서 6회로 늘면서 `/auth/register`의 분당 5회 rate limit(slowapi)에 걸려, 내 테스트와 무관한 "모바일 뷰포트" 테스트가 간헐적으로 실패하는 회귀를 직접 재현해 확인함(해당 테스트만 따로 실행하면 통과하는 것으로 rate limit이 원인임을 검증). 새 테스트를 독립적으로 추가하는 대신, 이미 로그인이 끝난 첫 번째 E2E 흐름(회원가입 → 계산 → 수정 → 삭제 → 로그아웃) 안에 필터 역전 검증을 끼워 넣어 회원가입 횟수를 원래 5회로 되돌리는 방식으로 해결
- 검증: vitest 14개·build·oxlint 기존과 동일하게 통과. Playwright E2E 5개 전체 재실행으로 rate limit 회귀 없이 모두 통과하는 것을 확인
