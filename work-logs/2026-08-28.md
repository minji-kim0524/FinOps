### 목적 및 이유
- "DB 마이그레이션 도구 도입 / 4대보험 요율 정확도 개선 / 직원별 통계·필터 확장 / 다른 제안" 중 직원별 통계·필터 확장을 다음 작업으로 선택
- 기존에는 계산 이력을 직원명으로 텍스트 검색만 할 수 있었고, 여러 직원의 이력이 섞여 있을 때 직원별로 총액·평균을 한눈에 비교할 방법이 없었음
- `main.py`: 월별/연도별 집계에 쓰이던 `_build_period_summary(records, period_key, date_format)`를, 날짜 포맷 대신 임의의 "레코드 → 그룹값" 함수를 받는 `_build_summary(records, group_key, group_value)`로 일반화. 월별/연도별 집계는 `lambda r: r.created_at.strftime(...)`을, 신규 직원별 집계는 `lambda r: r.employee_name or "(미지정)"`을 넘기는 방식으로 통일. `GET /records/summary/by-employee` 엔드포인트 신규 추가
- `App.jsx`: 필터 영역에 "직원 선택" `Select` 드롭다운을 추가. 현재 불러온 이력에서 중복 없는 직원명 목록을 자동으로 구성해 옵션으로 제공하며, 기존 텍스트 검색(`searchText`)과는 별개의 AND 조건으로 동작(정확히 일치하는 직원만 남김). "연도별 집계" 표 아래에 "직원별 집계" 표를 신규 추가하고, 컬럼 정의는 기존 `buildSummaryColumns` 헬퍼를 그대로 재사용
- `test_summary.py`: 직원별 집계가 빈 상태일 때와, 같은 직원의 여러 건이 올바르게 합산되고 직원명이 없는 건은 "(미지정)"으로 별도 집계되는지 검증하는 테스트 2개 신규 작성
- E2E 테스트: 직원별 집계 표가 추가되면서 계산 이력 표의 행을 찾던 기존 로케이터(`page.getByRole("row", { name: /홍길동/ })`)가 직원별 집계 표의 "홍길동" 행과도 매칭되어 모호해지는 회귀를 발견. `page.getByRole("table").first()`로 계산 이력 표(페이지에서 가장 먼저 렌더링되는 표)로 범위를 좁혀 해결
- 검증: pytest 65개, 프론트엔드 테스트 8개, Playwright E2E 2개 전부 통과. 브라우저에서 직접 홍길동 2건(각 300만원·500만원)·김철수 1건(400만원) 데이터를 만들어 직원 선택 드롭다운으로 "홍길동"만 필터링되는 것과, 직원별 집계 표에서 홍길동 2건의 총 공제액·총 실수령액·평균 실수령액이 정확히 합산되는 것을 확인
