# 2026-09-09

## `b314020` perf. 차트 컴포넌트 지연 로딩으로 초기 번들 축소 - GrossPayVsNetPayChart/MonthlyTrendChart를 React.lazy+Suspense로 분리해 recharts(gzip 약 110KB)를 초기 로딩에서 제외 - 프로덕션 빌드에서 vendor-recharts가 modulepreload 목록에서 빠진 것을 확인, vitest 14개/oxlint 통과

- 수정 파일: `frontend/src/App.jsx`

### 목적 및 이유
- `npm run build` 결과에 "vendor-antd 청크가 1100KB를 넘는다"는 경고가 계속 떠 있었는데, 이 프로젝트는 antd 하나만으로도 tree-shaking 후 ~1MB라 `vite.config.js`에 이미 `chunkSizeWarningLimit`을 올려두고 "실수로 전부 한 덩어리가 됐는지" 감지하는 용도로만 남겨둔 상태였음(antd 자체를 더 줄이는 건 라이브러리 교체가 필요해 이번 작업 범위 밖). 대신 실제로 줄일 여지가 있던 recharts(차트 라이브러리, gzip 약 110KB) 쪽을 최적화 대상으로 선택 — AskUserQuestion으로 제시한 후보(로그인 보안 강화, 프론트엔드 번들 크기 최적화, 백엔드 테스트 커버리지 측정) 중 사용자가 선택
- `App.jsx`에서 `GrossPayVsNetPayChart`/`MonthlyTrendChart`를 정적 import하고 있어서, 로그인 후 메인 화면을 그리는 데 recharts 전체가 항상 함께 로드되고 있었음. 두 컴포넌트를 `React.lazy(() => import(...))`로 바꾸고 각각 `Suspense`(fallback: 차트 높이(320px)만큼의 빈 영역, 레이아웃 흔들림 방지)로 감싸, recharts를 별도 청크로 분리해 실제 차트를 렌더링하는 시점에만 불러오도록 변경
- 검증: 프로덕션 빌드 후 `dist/index.html`의 `modulepreload` 목록에서 `vendor-recharts`가 빠진 것을 직접 확인(기존에는 vendor-antd/vendor-react와 함께 항상 선로딩됐음) — 초기 로딩에 필요한 JS가 recharts만큼(gzip 약 110KB) 줄어듦을 정적으로 확인. vitest 14개·oxlint 모두 기존과 동일하게 통과
- 로컬 dev 서버로 실제 로그인 후 화면을 렌더링해, 네트워크 로그에서 `GrossPayVsNetPayChart.jsx`/`MonthlyTrendChart.jsx`/`recharts.js`가 정상적으로 지연 요청되고 차트 섹션이 정상 표시되는 것을 확인. 이 과정에서 로컬스토리지에 남아있던 예전 토큰이 재기동한 백엔드에서 만료 처리되어 자동 로그아웃되는 현상을 겪었는데, 코드 버그가 아니라 테스트 환경(백엔드를 여러 번 재기동하며 JWT 유효성이 끊긴 상태)의 문제였음을 확인하고 새로 로그인해 정상 동작을 재확인
- 커밋 메시지 접두사를 두고 이 프로젝트의 커밋 컨벤션(Init/Feat/Remove/Fix/Docs/Style/Refactor/Test/Chore)에 `Perf`가 없다는 점을 사용자가 확인 요청 — 동작 변화 없이 코드 구조만 바꾼 점에서 `Refactor`로 묶는 방안을 제안했으나, 실제 커밋은 처음 제안했던 `perf.` 접두사로 진행됨
