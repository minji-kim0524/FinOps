- 수정 파일: `backend/app/main.py`, `backend/tests/test_auth.py`, `backend/tests/test_password.py`, `frontend/src/App.jsx`, `frontend/src/LoginPage.jsx`

### 목적 및 이유
- 보안/안정성 개선 항목 중 "비밀번호 최소 길이/복잡도 검증"을 먼저 진행. 지금까지는 빈 문자열만 아니면 어떤 비밀번호든 통과됐음
- 정책: **최소 8자, 영문자·숫자 각 1개 이상 포함**. 회원가입과 비밀번호 변경(새 비밀번호)에만 적용하고, **로그인은 검증 대상에서 제외** — 이미 저장된 계정의 비밀번호가 새 정책보다 약하더라도 로그인 자체는 계속 가능해야 하기 때문(안 그러면 기존 사용자가 갑자기 로그인을 못 하게 됨)
- `main.py`: 공용 검증 함수 `_validate_password_strength()` 추가. 기존 `AuthInput`(로그인/회원가입 공용)을 그대로 두면 로그인에도 검증이 걸려버리므로, 회원가입 전용 `RegisterInput`을 새로 분리해서 그쪽에만 Pydantic `field_validator`를 걸고, 로그인은 기존 `AuthInput`(검증 없음)을 그대로 사용하도록 정리. `ChangePasswordInput.new_password`에도 동일 검증 적용. 검증 실패 시 Pydantic이 자동으로 422를 반환
- `test_auth.py`: 기존 "회원가입 중복 아이디" 테스트가 쓰던 비밀번호("whatever")가 새 정책(숫자 없음)에 걸려서 "whatever123"으로 수정. 비밀번호가 너무 짧음/숫자 없음/영문자 없음 세 가지 케이스가 각각 422를 반환하는지 검증하는 테스트 3개 추가
- `test_password.py`: 비밀번호 변경 시 약한 새 비밀번호가 422로 거부되고 기존 비밀번호로는 계속 로그인되는지 검증하는 테스트 1개 추가 → 전체 34개 통과
- `frontend/LoginPage.jsx`: 회원가입 모드일 때만 비밀번호 필드에 강도 규칙(최소 8자, 영문자, 숫자)을 적용하고 안내 문구를 표시. 로그인 모드는 기존처럼 필수 입력만 검사
- `frontend/App.jsx`: 비밀번호 변경 모달의 새 비밀번호 필드에도 동일한 규칙과 안내 문구 추가
- 검증: pytest 34개, 프론트엔드 테스트 7개 전부 통과. 브라우저에서 실제로 약한 비밀번호("weak", "short")를 입력하면 서버에 요청을 보내기 전에 클라이언트 단에서 즉시 에러가 표시되는 것과, 정책을 만족하는 비밀번호로는 정상적으로 회원가입되는 것을 확인. 콘솔 에러 없음
