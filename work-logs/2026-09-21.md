### 목적 및 이유
- AskUserQuestion으로 제시한 후보(프론트엔드 테스트 커버리지 측정 도입, .env.example 파일 추가, 비밀번호 재설정 보안 답변 무차별 대입 방어) 중 사용자가 이 항목을 선택. 2026-09-12에 백엔드는 pytest-cov를 도입했지만 프론트엔드(vitest)는 그때도 지금도 커버리지가 측정된 적이 없었던 대칭적인 공백
- `@vitest/coverage-v8`을 설치하는 과정에서 `npm install`이 npm 자체 버그(arborist의 `#loadPeerSet`에서 TypeError)로 두 번 실패해 `--legacy-peer-deps`로 우회 설치했는데, 그 부작용으로 `@testing-library/dom`이 `node_modules`/`package-lock.json`에서 통째로 빠지면서 기존 테스트 2개가 즉시 깨지는 것을 발견. 플래그 없는 일반 `npm install`을 한 번 더 실행해 정상적인 의존성 트리로 복구했고, 기존 15개 테스트가 다시 통과하는 것으로 확인한 뒤 진행. `@vitest/coverage-v8`도 처음엔 latest(5.0.1)가 깔려 프로젝트의 vitest(4.1.10)와 메이저 버전이 어긋나 있어, 버전을 명시적으로 고정해 재설치함
- `vite.config.js`의 `test.coverage`에 v8 프로바이더와 `text`/`html` 리포터를 설정. React 루트를 마운트만 하는 진입점(`src/main.jsx`)은 단위 테스트로 검증할 로직이 없어 측정 대상에서 제외
- 첫 측정 결과 전체 55.37%(유틸 테스트 추가 전) — 컴포넌트·훅 단위 테스트가 애초에 많지 않고(이 프로젝트는 상호작용 검증을 주로 Playwright E2E가 담당하는 구조), 그중 `src/utils/format.js`(`formatWon`)와 `src/utils/download.js`(`downloadBlob`)는 다른 곳에서 광범위하게 재사용되는 순수 함수인데도 **완전히 0%**로 나와 명확한 gap이라 테스트를 채움. `downloadBlob`은 jsdom이 `URL.createObjectURL`을 구현하지 않아 직접 모킹하고, `HTMLAnchorElement.prototype.click`을 스텁해 실제 다운로드(네비게이션)는 막되 클릭 시점의 `download` 속성 값을 캡처해 검증하는 방식으로 작성
- 나머지 컴포넌트/훅들의 낮은 수치(App.jsx 44%, tableColumns.jsx 47%, useRecordExports.jsx 20% 등)는 이번 범위에서 억지로 채우지 않음 — "도입"이 목적이었지 전면적인 컴포넌트 테스트 작성은 별개의 큰 작업이라 판단. 대신 이 사실(낮은 수치가 곧 미검증을 뜻하지 않는다는 것과, 그 이유)을 README에 그대로 남겨 과장 없이 현재 상태를 기록
- `package.json`에 `npm run test:coverage` 스크립트를 추가하고, `.github/workflows/ci.yml`의 `frontend-build` 잡이 `npm run test`(테스트만) 대신 `npm run test:coverage`(커버리지 포함)를 실행하도록 바꾼 뒤 `frontend-coverage-report` 아티팩트를 업로드하도록 함 — 백엔드의 `coverage-report` 아티팩트와 동일한 패턴
