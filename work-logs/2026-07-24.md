## `b8d5fa5` init. 백엔드 초기셋팅 - FastAPI+pandas 급여 계산 로직 - pytest 단위 테스트

- 신규 파일: `.gitignore`, `backend/app/__init__.py`, `backend/app/calculator.py`, `backend/app/main.py`, `backend/requirements.txt`, `backend/tests/test_calculator.py`, `backend/tests/test_main.py`

### 목적 및 이유
- **1단계(계산 로직)** 구현: DB 없이 메모리 상에서만 "세전 급여 → 공제액 계산 → 실수령액" 파이프라인을 먼저 검증
- `calculator.py`: pandas로 국민연금(4.5%)·건강보험(3.545%)·장기요양보험(건강보험료의 12.95%)·고용보험(0.9%)을 비율 계산하는 방식으로 구현. 소득세/지방소득세의 간이세액표 반영이나 4대보험 요율의 연도별 변경·상한선 등 실무 정확도는 이후 확장 과제로 남겨두고, 이번 단계는 "pandas로 데이터를 다루는 법 학습"이 목적이므로 단순화된 비율 계산으로 시작
- `main.py`: FastAPI로 `POST /calculate` 엔드포인트 생성 — 세전 급여를 입력받아 계산 결과를 JSON으로 반환
- pytest로 계산 로직에 대한 단위 테스트 작성 (Jenkins 같은 CI 자동화 도구 대신, 이 단계에서는 로컬에서 바로 실행 가능한 pytest 단위 테스트로 검증하기로 결정)
- 검증: `uvicorn` 로컬 기동 + curl로 실제 API 응답 확인, pytest 전체 통과

## `8c3b8f9` feat. SQLite 저장 기능 추가 - SQLAlchemy 모델 및 DB 연결 - 계산 결과 저장/조회 엔드포인트 - 인메모리 DB 기반 pytest 테스트

- 신규 파일: `backend/app/database.py`, `backend/app/models.py`, `backend/tests/conftest.py`
- 수정 파일: `.gitignore`, `backend/app/main.py`, `backend/requirements.txt`, `backend/tests/test_main.py`

### 목적 및 이유
- **2단계(저장 기능)** 구현: 계산 결과가 서버 재시작 후에도 사라지지 않도록 SQLite + SQLAlchemy로 영속 저장 추가
- `database.py`: SQLite 연결 및 세션 설정
- `models.py`: 계산 결과를 저장할 `salary_records` 테이블 스키마 정의
- `main.py`: `POST /calculate`가 결과를 DB에 저장하도록 수정, 이력 조회용 `GET /records` 엔드포인트 추가
- `tests/conftest.py`: 테스트가 실제 DB 파일(`finops.db`)을 건드리면 테스트 간 데이터가 섞이므로, 인메모리 SQLite로 격리된 테스트 전용 DB를 fixture로 구성
- 검증: pytest 4개 통과, 실제 서버로 계산→저장→`/records` 조회 흐름 curl 확인
