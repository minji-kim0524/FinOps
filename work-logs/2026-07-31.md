### 목적 및 이유
- **10단계(기본 인증 추가)** 진행: 지금까지는 누구나 급여 계산·조회·수정·삭제가 가능했는데, 로그인한 사용자만 접근할 수 있도록 보호
- `auth.py`: 비밀번호는 `bcrypt`로 해싱해서 저장(평문 저장 금지), 로그인 성공 시 `pyjwt`로 JWT 액세스 토큰 발급. `get_current_user`가 요청의 토큰을 검증해 유효하지 않으면 401 반환
- `models.py`: `User` 테이블(username, hashed_password) 추가
- `main.py`: `POST /auth/register`, `POST /auth/login` 엔드포인트 추가. 기존 급여 관련 엔드포인트(`/calculate`, `/calculate/bulk`, `/records`, `PUT`/`DELETE /records/{id}`) 전부에 `get_current_user` 의존성을 걸어 토큰 없이는 접근 불가하도록 보호
- JWT 시크릿 키는 `JWT_SECRET_KEY` 환경변수로 설정 가능하고, 미설정 시 개발용 기본값을 사용 — 실제 운영 배포 시엔 반드시 별도 값으로 교체 필요 (코드 주석에 명시)
- `conftest.py`: 인증이 걸리면서 기존 테스트들이 전부 401로 실패하게 되는 것을 막기 위해, 테스트 클라이언트가 픽스처 단계에서 자동으로 회원가입·로그인해 토큰을 기본 헤더에 실어두도록 처리 — 기존 테스트 코드는 손대지 않고 그대로 통과
- `test_auth.py`: 회원가입, 중복 아이디, 로그인 성공/실패, 토큰 없음/잘못된 토큰 케이스 등 6개 테스트 추가 → 전체 18개 통과
- `frontend/api.js`: axios 인스턴스에 요청 인터셉터를 걸어, `localStorage`에 저장된 토큰을 모든 API 요청에 자동으로 실어 보내도록 처리
- `frontend/LoginPage.jsx`: 로그인/회원가입을 토글로 전환하는 폼 컴포넌트 신규 작성
- `frontend/App.jsx`: 토큰이 없으면 로그인 화면, 있으면 기존 계산기 화면을 보여주도록 분기. 헤더에 로그아웃 버튼 추가. 서버가 401/403을 반환하면(토큰 만료 등) 자동으로 로그아웃 처리하도록 공통 에러 핸들러(`reportError`) 추가
- 검증: 브라우저에서 회원가입 → 자동 로그인 → 급여 계산 → 로그아웃 → 같은 계정으로 재로그인 시 이전 데이터가 그대로 유지되는 것까지 실제로 확인. `curl`로 토큰 없이 `/records` 호출 시 401이 반환되는 것도 별도로 확인. 콘솔 에러 없음
