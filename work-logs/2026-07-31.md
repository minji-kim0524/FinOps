## 작업2. `c6b7c1b` feat. 사용자별 계산 이력 분리 - SalaryRecord에 owner_id 추가 - 조회/수정/삭제 API를 소유자 기준으로 제한 - pytest 이력 격리 테스트 추가

- 신규 파일: `backend/tests/test_ownership.py`
- 수정 파일: `backend/app/main.py`, `backend/app/models.py`

### 목적 및 이유

- **11단계(사용자별 이력 분리)** 진행: 10단계에서 로그인 인증은 추가했지만, 계산 이력 자체에는 "누가 만들었는지" 정보가 없어서 로그인만 하면 다른 사용자의 이력까지 전부 보이는 문제가 있었음. 이를 이어서 해결
- `models.py`: `SalaryRecord`에 `owner_id`(`users.id` 참조) 컬럼 추가
- `main.py`: 계산 결과 저장 시(`_save_calculated`) 로그인한 사용자의 id를 `owner_id`로 함께 저장. `GET /records`는 `current_user.id`로 필터링해서 본인 이력만 반환. `_get_record_or_404`가 record id뿐 아니라 `owner_id`까지 같이 검사하도록 바꿔서, 다른 사용자의 이력을 수정(`PUT`)·삭제(`DELETE`)하려 하면 "존재하지 않음(404)"으로 응답 — 실제로 존재하는지 여부 자체를 숨겨 정보 노출을 막음
- `test_ownership.py`: 다른 사용자의 이력이 목록에 안 보이는지, 수정 시도가 막히는지, 삭제 시도가 막히는지 각각 검증하는 테스트 3개 추가 → 전체 21개 통과
- 검증: `curl`로 alice/bob 두 계정을 만들어 실측 — bob이 `/records`를 조회해도 alice의 이력은 안 보이고, bob이 alice의 이력 id로 `PUT`/`DELETE`를 시도해도 둘 다 404가 반환되며 alice의 데이터는 그대로 보존됨을 확인
- 참고: `owner_id`는 새로 추가된 필수 컬럼이라, 기존에 만들어 둔 로컬 SQLite(`finops.db`)나 Docker Postgres 볼륨은 예전 스키마 그대로라 재사용 시 오류가 날 수 있음 — 로컬은 `finops.db` 삭제, Docker는 `docker compose down -v`로 초기화 필요
