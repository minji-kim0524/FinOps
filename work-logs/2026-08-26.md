### 목적 및 이유
- "DB 마이그레이션 도구 도입 / 4대보험 요율 정확도 개선 / 연간 집계·통계 기능 확장 / 다른 제안" 중 연간 집계·통계 기능 확장을 다음 작업으로 선택
- 기존에는 월별 집계만 있고, 월별 데이터를 시간 흐름에 따라 한눈에 비교할 수 있는 그래프도 없었음(기존 막대 그래프는 개별 계산 건을 비교하는 용도라 시계열 추이를 보여주지 못함)
- `main.py`: 기존 `monthly_summary`에 있던 groupby 집계 로직을 `_build_period_summary(records, period_key, date_format)` 공통 헬퍼로 추출. `period_key`/`date_format`만 다르게 넘겨 월별("%Y-%m")과 연도별("%Y") 집계를 같은 코드로 처리하도록 리팩터링한 뒤, `GET /records/summary/yearly` 엔드포인트 신규 추가
- `App.jsx`: `SUMMARY_COLUMNS`를 `buildSummaryColumns(periodTitle, periodKey)` 함수로 바꿔 월별/연도별 표가 컬럼 정의를 공유하도록 함. 기존 "월별 집계" 표 위에 Recharts `LineChart`로 "월별 추이"(총 세전 급여·총 실수령액 추이) 그래프를 추가하고, "월별 집계" 표 아래에 "연도별 집계" 표를 신규 추가
- `test_summary.py`: 연도별 집계가 빈 상태일 때와, 서로 다른 연도의 이력이 올바르게 그룹핑·합산되는지 검증하는 테스트 2개 신규 작성 (기존 월별 집계 테스트와 동일한 패턴으로 특정 레코드의 `created_at`을 과거로 조작해 검증)
- `App.test.jsx`: 메인 화면 진입 시 `/records/summary/yearly`도 함께 호출되는지 확인하는 어서션 추가
- 검증: pytest 63개, 프론트엔드 테스트 8개, Playwright E2E 2개 전부 통과. 2024/2025(같은 해 2건)/2026년에 걸쳐 백데이트한 테스트 데이터로 브라우저에서 직접 확인 — 월별 추이 그래프, 월별 집계, 연도별 집계(2025년 2건이 정확히 합산되는 것 포함) 모두 올바른 값으로 렌더링되는 것을 확인
