## `a4b4492` feat. Render 배포 준비 - CORS/포트/API 주소 환경변수화 - 인증 불필요한 /health 엔드포인트 추가 - render.yaml Blueprint 작성 (백엔드/프론트엔드/DB)

- 신규 파일: `render.yaml`
- 수정 파일: `backend/Dockerfile`, `backend/app/main.py`, `frontend/src/api.js`

### 목적 및 이유
- **12단계(클라우드 배포)** 착수: 지금까지 로컬/Docker에서만 돌리던 프로젝트를 실제 인터넷에서 접근 가능한 환경(Render)에 올리기 위한 준비 작업. 배포 플랫폼은 Vercel(프론트엔드 전용, 백엔드/DB 미지원)과 Railway를 비교한 뒤, 지금 구조(FastAPI+React+PostgreSQL)를 한 곳에서 다 호스팅할 수 있고 기존 `docker-compose.yml` 스타일과 비슷하게 `render.yaml`로 코드화할 수 있는 **Render**로 결정
- `main.py`: CORS 허용 origin을 코드에 하드코딩(`http://localhost:5173`)하지 않고 `CORS_ORIGINS` 환경변수로 설정 가능하게 변경 — 배포 후 실제 프론트엔드 도메인을 허용해야 하기 때문. 인증 없이 접근 가능한 `GET /health` 엔드포인트 추가 — Render가 서비스 상태를 주기적으로 확인(헬스체크)할 공개 엔드포인트가 필요해서
- `Dockerfile`: Render는 컨테이너가 어떤 포트를 열지 `PORT` 환경변수로 알려주는 방식이라, `uvicorn` 실행 포트를 하드코딩된 8000 대신 `${PORT:-8000}`으로 변경(로컬 docker-compose는 기존처럼 8000 기본값으로 그대로 동작)
- `frontend/api.js`: 백엔드 주소를 하드코딩(`http://localhost:8000`) 대신 `VITE_API_BASE_URL` 빌드 환경변수로 설정 가능하게 변경 — 배포 후에는 실제 백엔드 도메인을 가리켜야 하기 때문
- `render.yaml`: PostgreSQL, 백엔드(Docker 웹서비스), 프론트엔드(정적 사이트) 3개 서비스를 하나의 Blueprint로 정의. `CORS_ORIGINS`/`VITE_API_BASE_URL` 값은 실제 배포 전에는 정확한 URL을 알 수 없어 placeholder로 넣어두고, 첫 배포 후 실제 할당된 URL로 교체가 필요함을 파일 내 주석으로 명시
- 검증: pytest 21개 통과(변경이 기존 동작에 영향 없음 확인), `/health` 엔드포인트 응답 확인, `npm run build`로 프론트엔드 프로덕션 빌드 성공, `docker compose up --build`로 새 Dockerfile(`$PORT` 기본값 포함)이 로컬에서도 정상 동작하는 것까지 확인
- 참고: 실제 Render 계정 생성·Blueprint 연결·배포는 계정 생성이 필요한 작업이라 직접 진행해야 함 (본 커밋은 그 이전 단계인 "배포 가능한 상태로 코드/설정 준비"까지)
