## `7436706` feat. 계산 이력 검색 필터 확장 - 기간(RangePicker)·급여액 범위 필터 추가 - 계산일시 컬럼 추가 - API 응답에 created_at 노출 - pytest/vitest 테스트 보강

- 수정 파일: `backend/app/main.py`, `backend/tests/test_main.py`, `frontend/package.json`, `frontend/package-lock.json`, `frontend/src/App.jsx`

### 목적 및 이유
- **24단계(계산 이력 검색 필터 확장)** 진행: 지금까지는 직원명으로만 검색이 가능했는데, 실무에서는 "이번 달에 계산한 것만", "특정 급여 구간만" 같은 조건으로 이력을 좁혀볼 필요가 있어서 필터를 확장
- `main.py`: `_serialize()` 응답에 `created_at`(ISO 문자열)을 추가 — 17단계(월별 집계)에서 이미 DB 컬럼은 있었지만 API 응답에는 노출되지 않고 있었어서, 프론트엔드가 기간 필터를 적용하려면 먼저 이 값을 받을 수 있어야 했음
- `test_main.py`: `/calculate` 응답의 `created_at`이 올바른 ISO 형식인지 검증하는 assertion 추가 → 전체 30개 통과
- `frontend/App.jsx`:
  - 이력 표에 **"계산일시"** 컬럼 추가(정렬 가능, `dayjs`로 포맷)
  - 검색 영역을 직원명 검색 하나에서 **기간(`DatePicker.RangePicker`) + 최소/최대 세전 급여(`InputNumber`)**까지 확장하고, "필터 초기화" 버튼 추가
  - `filteredRecords`가 이름/기간/급여 범위를 모두 AND 조건으로 필터링하도록 로직 확장, 아래 차트(세전 급여 vs 실수령액)도 필터링된 결과에 자동 연동됨 (월별 집계 표는 서버 집계라 필터와 무관하게 전체 기준 유지 — 의도된 동작)
  - `dayjs`를 명시적 의존성으로 추가 (기존엔 antd 내부적으로만 쓰이던 걸 직접 import해서 씀)
- 검증: 프론트엔드 테스트 7개 회귀 없이 통과. 브라우저에서 실제로 홍길동(300만원)·박영희(600만원) 두 건을 계산한 뒤, 최소 급여 400만원 필터를 걸어 박영희만 남고 차트도 함께 갱신되는 것을 확인 → "필터 초기화"로 두 건이 다시 모두 보이는 것까지 확인. 콘솔 에러 없음
