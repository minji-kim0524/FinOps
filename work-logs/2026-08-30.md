- 현재 `User`/`SalaryRecord` 전체 스키마를 담은 baseline 마이그레이션(`7830c4aadf24_initial_schema.py`)을 autogenerate로 생성. 생성 직후 재실행해 diff가 없는지, upgrade/downgrade가 정상 왕복되는지 직접 검증
- `main.py`의 `Base.metadata.create_all(bind=engine)` 제거. 대신 `Dockerfile`의 `CMD`와 `playwright.config.js`의 백엔드 기동 커맨드가 `alembic upgrade head`를 먼저 실행한 뒤 서버를 띄우도록 변경. pytest는 테스트마다 새로 만드는 인메모리 SQLite에 기존처럼 `create_all`을 그대로 사용하므로 영향 없음
- README에 로컬 개발 시 최초 `alembic upgrade head` 필요, 모델 수정 시 `alembic revision --autogenerate`로 마이그레이션 생성하는 절차 추가
- 검증: pytest 65개, Playwright E2E 2개 전부 통과(E2E 실행 로그에서 `alembic upgrade head`가 자동 실행되는 것도 확인). 이 변경 자체가 스키마 관리 방식을 바꾸는 것이라, Render의 기존 Postgres에 이미 테이블이 있으면 배포 시 "테이블이 이미 존재함" 에러가 나는 것을 미리 인지하고 사용자에게 안내함
- 후속 조치: 사용자가 Render 대시보드에서 psql로 접속해 기존 `salary_records`, `users` 테이블을 직접 DROP한 뒤, `git push origin main`으로 배포를 트리거함 (이번이 마지막 초기화이고, 이후로는 마이그레이션으로 무중단 스키마 변경이 가능해짐)

## `4539ed0` fix. 로그인/회원가입 실패 원인 안내 개선 - 백엔드 연결 불가(네트워크 오류)와 실제 검증 실패를 구분하지 못하던 문제 해결 - 회원가입 시 아이디 중복/비밀번호 조건 미달 등 실제 사유를 그대로 표시 - 오류 메시지 분기 로직을 순수 함수로 분리해 테스트 안정성 확보

- 수정 파일: `frontend/src/LoginPage.jsx`, `frontend/src/LoginPage.test.jsx`

### 목적 및 이유
- 로컬에서 회원가입을 시도했는데 실패 원인이 안내되지 않는다는 문제 제보로 시작. 원인을 재현해보니 로컬 백엔드 서버 자체가 꺼져 있었는데, 기존 코드는 이런 네트워크 오류(응답 없음)와 실제 도메인 오류(아이디 중복, 비밀번호 조건 미달 등)를 구분하지 않고 전부 "회원가입에 실패했습니다"로 뭉뚱그리고 있어서 원인 파악이 불가능했음
- `describeAuthError(err, mode)` 함수로 오류 분기 로직을 컴포넌트에서 분리: 응답 자체가 없으면(네트워크/서버다운) 전용 메시지, 429는 기존 rate limit 메시지, 회원가입 중 아이디 중복(400)은 전용 메시지, 회원가입 중 검증 실패(422)는 백엔드가 이미 한글로 작성해 둔 실제 사유(`extractValidationMessage`로 pydantic detail 배열에서 추출)를 그대로 노출. 로그인 실패는 계정 존재 여부를 유추할 수 없도록 기존처럼 공통 메시지 유지
- 비밀번호 재설정 흐름(보안 질문 조회, 비밀번호 재설정)에도 동일하게 네트워크 오류 구분을 추가
- 테스트 작성 중, 회원가입 폼의 antd `Select`(보안 질문) 클릭 상호작용이 jsdom 환경에서 테스트 순서에 따라 불안정하게 동작하는 것을 발견 — 이전 테스트의 드롭다운 포털이 완전히 정리되기 전에 다음 테스트가 같은 텍스트를 조회해 엉뚱한 걸 클릭하는 것으로 추정됨. 이를 근본적으로 피하기 위해 `describeAuthError`/`extractValidationMessage`를 export해 UI 렌더링 없이 순수 함수 단위로 직접 테스트하는 방식으로 전환
- 검증: 프론트엔드 테스트 14개(신규 7개 포함) 전부 통과, 백엔드 65개 회귀 없음. 브라우저에서 백엔드를 끈 상태로 로그인 시도 → 새 네트워크 오류 메시지 노출, 백엔드를 켠 뒤 존재하지 않는 계정으로 시도 → 기존처럼 "아이디 또는 비밀번호가 올바르지 않습니다"로 정상 구분, 실제 회원가입도 정상 동작하는 것까지 실측 확인

## `6e8c28e` fix. 로그인/회원가입 화면 아이디 형식 안내 및 좌측 정렬 - 아이디 입력창에 예시(placeholder/hint) 추가 - #root의 text-align: center가 로그인 화면에 상속되던 문제 수정

### 목적 및 이유

- `LoginPage.jsx`: 아이디 `Input`에 `placeholder="예: minji123"` 추가. 회원가입 모드에서는 비밀번호 필드처럼 `extra="예: minji123"` 힌트 텍스트도 함께 노출(로그인 모드는 placeholder만)
- 힌트 텍스트를 추가하고 보니 로그인 화면 전체(카드 제목, 힌트 텍스트 등)가 가운데 정렬로 보이는 것을 발견. 원인은 `index.css`의 `#root { text-align: center; }`(Vite 템플릿 기본값 잔재)가 로그인 화면에 그대로 상속되고 있었기 때문 — 메인 앱 화면(`.app`)은 이미 `text-align: left`로 덮어써서 문제가 없었지만 로그인 화면(`.login-page`)에는 그 처리가 빠져 있었음
- `App.css`의 `.login-page`에 `text-align: left`를 추가해 로그인 화면 전체를 좌측 정렬로 통일
- 검증: 프론트엔드 테스트 14개 회귀 없이 통과. 브라우저에서 로그인/회원가입 모드 모두 힌트 텍스트와 카드 레이아웃이 좌측 정렬로 표시되는 것을 확인
