### 목적 및 이유
- **19단계(비밀번호 재설정 기능)** 진행: 이메일 시스템이 없는 프로젝트라 "비밀번호를 잊었을 때 이메일로 복구"하는 정식 flow는 구현할 수 없어서, 범위를 "로그인한 상태에서 현재 비밀번호를 확인하고 새 비밀번호로 바꾸는 기능"으로 좁혀서 진행
- `main.py`: `PUT /auth/password` 추가 — 현재 비밀번호를 `verify_password`로 검증한 뒤 새 비밀번호를 해싱해서 저장. 틀린 현재 비밀번호는 의도적으로 **401이 아니라 400**으로 응답하도록 설계함 — 401은 "토큰이 유효하지 않음(로그인 만료)"을 뜻하는데, "현재 비밀번호가 틀림"은 그것과 다른 종류의 에러라서 프론트엔드가 두 경우를 구분해서 처리할 수 있도록 상태 코드를 분리
- `test_password.py`: 정상 변경 후 옛 비밀번호로는 로그인 실패·새 비밀번호로는 로그인 성공, 틀린 현재 비밀번호는 400, 미인증 요청은 401을 각각 검증하는 테스트 3개 추가 → 전체 28개 통과
- `frontend/App.jsx`: 헤더에 "비밀번호 변경" 버튼과 현재/새/새 비밀번호 확인 3개 필드로 구성된 모달 추가. 새 비밀번호와 확인란이 다르면 폼에서 즉시 검증 에러를 보여줌. 응답이 400이면 "현재 비밀번호가 올바르지 않습니다"로 안내하고, 401/403일 때만 세션 만료로 판단해 자동 로그아웃 — 비밀번호를 틀렸다고 실수로 로그아웃되는 일이 없도록 기존 `reportError` 공통 처리와 분리
- 검증: 브라우저에서 회원가입 → 비밀번호 변경 → 로그아웃 → 옛 비밀번호로 로그인 시도(실패 확인) → 새 비밀번호로 로그인(성공 확인)까지 실제로 수행. 중간에 브라우저 자동 입력 아티팩트로 로그인이 한 번 실패했는데, `curl`로 백엔드를 직접 호출해 실제로는 정상 동작함을 먼저 확인한 뒤 입력 필드를 다시 채워 재현 — 실제 버그가 아니라 테스트 조작 중 발생한 오류였음을 구분해 확인. 콘솔에는 의도된 실패 로그인 시도의 401 네트워크 로그만 있고 런타임 에러 없음
