## `c7452e3` refactor. 로그인 화면 초기 로딩 경량화(AppContent 지연 로딩) - 로그인 이후 화면(Table/DatePicker/Upload 등)을 AppContent.jsx로 분리해 React.lazy로 지연 로딩 - antd/recharts를 강제로 한 청크에 묶던 vite 설정을 제거(지연 로딩을 무력화하던 원인) - 로그인 화면 필요 JS 약 387KB→256KB(gzip, 34% 감소), index.html title/lang 오류 수정 - vitest 47개/E2E 5개 통과, 프로덕션 빌드로 청크 분리 실측 확인

- 신규 파일: `frontend/src/AppContent.jsx`
- 수정 파일: `frontend/index.html`, `frontend/src/App.jsx`, `frontend/vite.config.js`

### 목적 및 이유
- 이번엔 AskUserQuestion으로 후보를 고르는 대신, 사용자가 "현재 lcp, performance 등 성능향상을 진행해줘"라고 직접 지시. 로그인 화면 뒤에 있는 앱이라 실제 방문자가 처음 보는 화면(LCP 대상)은 로그인 폼이라는 점에 착안해, "로그인 화면이 정말 필요로 하는 JS가 얼마나 되는지"부터 측정
- `dist/index.html`의 `modulepreload` 목록을 확인해보니, `App.jsx`가 로그인 여부와 무관하게 `Table`을 최상단에서 import하고 있어서(로그인 이후 화면인 `AppContent` 함수가 `App.jsx` 안에 그대로 있었음), 로그인 화면만 보고 이탈하는 방문자도 Table/DatePicker/Upload 등 로그인 후에만 쓰는 antd 컴포넌트의 무게를 전부 미리 받고 있었음. 이건 이전(2026-09-09)에 recharts 차트 2개를 지연 로딩했던 것과 같은 종류의 문제가 "화면 단위"로 한 번 더 있었던 것
- `AppContent`(이력 표·필터·CSV 업로드·차트·집계를 담당하던 코드 전체)를 `frontend/src/AppContent.jsx`로 통째로 옮기고, `App.jsx`에서 `React.lazy(() => import("./AppContent"))`로 지연 로딩하도록 수정. 로그인 성공 시에만 이 청크를 받아오게 됨
- **1차 시도가 예상과 다르게 동작한 것을 실측으로 발견**: 지연 로딩만 적용하고 빌드해보니, `vite.config.js`의 기존 `manualChunks` 설정이 antd/recharts 관련 모듈을 "정적/동적 import 경로와 무관하게" 전부 강제로 하나의 이름 있는 vendor 청크(`vendor-antd`, `vendor-recharts`)로 몰아넣고 있었고, Vite가 이렇게 수동으로 이름 붙인 청크는 실제 도달 가능 여부와 상관없이 `modulepreload`로 미리 받아오는 것을 `dist/index.html`을 직접 열어보고 확인함 — 즉 기존 설정이 방금 만든 지연 로딩을 그대로 무력화하고 있었음(recharts조차 로그인 화면에서 `modulepreload`되고 있었음). `manualChunks`에서 antd/recharts 강제 규칙을 제거하고 Rollup의 자동 분할에 맡기도록 바꾸자 실제로 청크가 분리되어 `modulepreload` 목록에서 빠지는 것을 재확인
- `chunkSizeWarningLimit`도 예전 "antd 하나로 뭉친 덩어리(~1.1MB)" 기준에서, 지금 남은 가장 큰 공용 청크(`preload-helper`, ~515KB — 로그인 화면이 실제로 쓰는 Form/Modal/Select 등 antd 공용 런타임)에 맞춰 520으로 다시 조정
- 지나가다 `frontend/index.html`의 `<title>frontend</title>`(Vite 스캐폴드 기본값이 그대로 남아있던 것)와 `<html lang="en">`(전체가 한국어 UI인데 영어로 표시돼 스크린리더 등에 잘못된 언어 힌트를 주던 것)도 함께 수정 — 둘 다 비용이 거의 없고 명백한 오류라 별도 논의 없이 같이 고침
- 검증: vitest 47개(App.jsx가 AppContent를 Suspense로 감싸 지연 로딩해도 App.test.jsx의 `findByRole` 기반 비동기 대기가 문제없이 통과), build·oxlint 통과. Playwright E2E 5개도 통과해 지연 로딩된 화면에서 계산/수정/삭제 등 전체 흐름이 여전히 정상 동작함을 확인. 마지막으로 `vite preview`로 실제 프로덕션 빌드를 띄우고 브라우저에서 직접 확인: 로그인 화면에서는 4개 파일(`index`, `clsx`, `vendor-react`, `preload-helper`)만 받아오고, 로그인 후에야 `AppContent`/`CartesianChart`(recharts)/차트 2종 청크가 새로 요청되는 것을 네트워크 요청으로 확인. 이 과정에서 `vite preview`(4173번 포트)가 백엔드 CORS 허용 목록(`localhost:5173` 기본값)에 없어 API 요청이 막히는 것도 발견해, `CORS_ORIGINS` 환경변수로 임시 허용해 실제 데이터가 반영된 화면까지 최종 확인
- 실측(gzip 기준): 로그인 화면에 필요한 JS가 약 387KB → 약 256KB로 약 34% 감소(`vendor-react` 59.64KB + `preload-helper` 174.52KB + `index` 21.08KB). recharts(~110KB)와 `AppContent`(137.38KB)는 로그인 후에만 받아옴. 여전히 `preload-helper`(antd 공용 런타임)가 가장 큰 덩어리로 남아있는데, 로그인 화면 자체가 쓰는 antd 구성 요소라 이번 범위에서는 더 줄이기 어려운 것으로 판단하고 남겨둠
