# 2026-09-26

## `65be1dd` feat. 집계 API를 SQL GROUP BY로 전환 - /records/summary 3종이 요청마다 전체 이력을 메모리로 올려 pandas로 집계하던 것을 DB 집계(summarize_by_month/year/employee)로 교체 - 이력 5만 건 기준 SQLite 1,066ms→67ms, PostgreSQL 1,053ms→30ms - 기존 pandas 결과와 SQLite/PostgreSQL 모두 완전 일치 검증, 소유권 격리 테스트 추가(pytest 104개/E2E 5개 통과)

- 수정 파일: `backend/app/routers/records.py`, `backend/app/services/records.py`, `backend/tests/test_summary.py`

### 목적 및 이유
- AskUserQuestion으로 제시한 후보(집계 API 성능 개선, 비밀번호 재설정 보안 답변 방어) 중 사용자가 이 항목을 선택. 이틀 전 프론트엔드 초기 로딩을 다뤘던 성능 작업의 백엔드 쪽 후속으로, `/records/summary`·`/records/summary/yearly`·`/records/summary/by-employee`가 요청마다 사용자의 **전체 이력을 파이썬 객체로 모두 올린 뒤 pandas DataFrame으로 groupby**하고 있어 이력이 늘수록 느려지는 구조였음. 화면 진입·계산·수정·삭제·CSV 업로드마다 `refreshAll`이 이 3개를 매번 호출하므로 체감 영향이 큼
- **수정 전에 baseline부터 측정**: 임시 벤치 스크립트(scratchpad, 프로젝트 코드 아님)로 이력 1천/1만/5만 건을 넣고 집계 3종 호출 시간을 측정 → 선형(O(N))으로 증가해 5만 건에서 약 1.07초
- 구현: `services/records.py`의 `get_owned_records_by_created_at`+`build_group_summary`(pandas)를 제거하고, DB가 직접 집계하는 `_aggregate_by`(`func.count/sum/avg` + `group_by`)와 `summarize_by_month/year/employee`로 교체. 세부 결정: (1) 월/연도는 SQLite의 `strftime`과 PostgreSQL의 `to_char`가 달라 방언 분기를 만들지 않고 양쪽에서 같은 결과를 내는 `extract("year"/"month")`를 쓰고 키 문자열은 파이썬에서 조립 (2) 직원명 "(미지정)" 처리는 `coalesce(nullif(name, ''), '(미지정)')`로 SQL에서 처리해 기존처럼 빈 이름과 리터럴 "(미지정)"이 한 그룹으로 합쳐지게 함 (3) 정렬은 DB `ORDER BY`가 콜레이션(로케일)에 따라 한글/영문 순서가 달라질 수 있어, 그룹 수가 매우 적다는 점을 이용해 기존과 같은 코드포인트 순서를 보장하도록 파이썬에서 정렬 (4) 평균은 `round(float(avg))`로 기존 pandas `.round()`와 같은 반올림 규칙(짝수 쪽) 유지
- **"결과가 정말 같은가"를 가장 신경 써서 검증**: 기존 pandas 알고리즘을 그대로 옮긴 기준(reference) 구현과 새 구현을, 무작위 이력 3천 건(빈 이름·"(미지정)" 이름·다국어 이름, 연말/연초 경계 날짜, 평균이 정확히 .5로 떨어지는 경우, 사용자 2명, 이력 없는 사용자)에서 비교해 **SQLite와 PostgreSQL 모두 100% 일치**함을 확인. 로컬에 PostgreSQL이 안 떠 있어서, 이전 작업(DB 백업 스크립트 검증)에서 썼던 방식대로 `initdb`/`pg_ctl`로 임시 클러스터를 띄워 배포 DB 방언에서도 직접 확인한 뒤 정리
- 개선 후 재측정(집계 3종 합계, 5만 건 기준): SQLite 1,066ms → 67ms(약 16배), PostgreSQL 1,053ms → 30ms(약 35배). PostgreSQL의 수정 전 수치는 `git worktree`로 HEAD 코드를 임시로 체크아웃해 같은 벤치를 돌려 공정하게 비교(작업 후 worktree는 정리)
- 테스트: 기존 집계 테스트(월/연도/직원 그룹핑·빈 결과·미지정)가 수정 없이 그대로 통과. 추가로 (1) 집계가 이제 DB GROUP BY라 소유자 필터가 빠지면 다른 사용자 합계가 섞일 수 있으므로 "내 집계에 타인 이력이 섞이지 않는다" 회귀 테스트, (2) 평균이 정수로 반올림되는지 테스트를 추가. 처음 작성한 두 번째 테스트는 이름/주석이 ".5 반올림"이라고 돼 있었지만 실제 데이터는 3,652,550.333…이라 검증 내용과 맞지 않아 바로 정정(진짜 .5 tie 케이스는 위의 DB 비교 스크립트에서 별도로 확인)
- 검증: pytest 104개(기존 102 + 신규 2) 통과, 커버리지 99% 유지(`services/records.py` 100%), Playwright E2E 5개 통과. API 응답 스키마와 값이 동일해 프론트엔드는 수정하지 않음
