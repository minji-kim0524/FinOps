### 목적 및 이유
- "DB 마이그레이션 도구 도입 / 4대보험 요율 정확도 개선 / 급여명세서 PDF 다운로드 / 다른 제안" 중 급여명세서 PDF 다운로드를 다음 작업으로 선택
- PDF 생성 라이브러리는 시스템 의존성(cairo/pango 등)이 필요한 `weasyprint` 대신, 순수 파이썬으로 동작하는 `reportlab`을 선택. 다만 한글은 기본 내장 폰트로 렌더링이 안 되기 때문에 별도의 한글 지원 폰트를 등록해야 하는 제약이 있음을 확인
- 폰트 파일을 리포지토리에 직접 커밋하는 대신(라이선스·바이너리 관리 부담), 배포 환경(Debian 기반 Docker)에는 `apt-get install fonts-nanum`으로 나눔고딕을 설치하도록 Dockerfile을 수정. GitHub Actions CI(backend-tests, e2e-tests 두 job)도 동일한 이유로 `fonts-nanum`을 설치하는 단계를 추가하지 않으면 PDF 생성 시 500 에러가 나므로 함께 반영
- `payslip.py`: `_FONT_CANDIDATES` 목록에 리눅스 배포 경로(`/usr/share/fonts/truetype/nanum/NanumGothic.ttf`)와 로컬 macOS 개발 환경에서 기본 내장된 `AppleGothic.ttf` 경로를 순서대로 두어, 어느 쪽이든 있는 폰트를 자동으로 찾아 등록하도록 구현. 폰트를 하나도 찾지 못하면 원인을 바로 알 수 있도록 명확한 에러 메시지를 던지게 함
- `main.py`: `GET /records/{record_id}/payslip` 엔드포인트 신규 추가. 기존 수정/삭제 엔드포인트와 동일하게 `_get_record_or_404`로 소유권 검증 후 PDF를 스트리밍 응답으로 반환
- `frontend/App.jsx`: 이력 표의 "관리" 컬럼에 "명세서" 버튼을 추가. 기존 엑셀 내보내기와 동일한 blob 다운로드 패턴을 재사용
- `test_payslip.py`: PDF 정상 생성(응답이 `%PDF`로 시작하는지, Content-Type/파일명 확인), 존재하지 않는 이력 404, 다른 사용자의 이력에는 접근할 수 없는지(404) 3개 테스트 작성
- E2E 테스트: 기존 회원가입→계산→수정→삭제 흐름 중 계산 직후 단계에 "명세서" 버튼 클릭 시 실제 다운로드 이벤트가 발생하고 파일명이 `payslip_{id}.pdf` 형식인지 검증하는 단계를 추가
- 검증: pytest 61개, 프론트엔드 테스트 8개, Playwright E2E 2개 전부 통과. 브라우저에서 직접 회원가입 → 세전 300만원 계산 → 명세서 다운로드까지 수행해 PDF를 내려받았고, 다운로드된 PDF를 직접 열어 제목·직원명·계산일시·항목별 공제액·실수령액이 한글로 깨짐 없이 정확한 금액과 함께 렌더링되는 것을 확인
